## 根因与修复

审计了实际源脚本、旧暂存发布脚本和 V0.5.1 ZIP 内脚本。两轮修复仍失败有四个相连原因：

1. V0.5.1 ZIP 使用了旧暂存目录中的脚本，与项目根目录源文件内容不同；实际发布包回退了稳定 ID 优先逻辑。
2. `inspectCurrent()` 仍先用昵称筛选联系人；标题不同会在稳定 ID 比较前把候选清空。
3. `verifyOpenConversation()` 先做昵称判断，ID 判断较晚；旧测试只覆盖了有限 ID 节点，没有覆盖包装祖先上的 ID，也没有要求详情 ID 与选中行 ID 同时一致。
4. `contactFromRow()` 对 `SELECTORS.title` 的父容器直接读 `textContent`，复合标题中的姓名和星期/时间子项会被拼成一个显示名。局部单测没有复现这个 DOM 结构，也没有覆盖“找候选 → 核验 → applyDetail → 持久化”的完整流程。

V0.5.2 已重做身份流程。显示名存于 `displayName`，身份主键存于 `conversationStableId`；类型为 `PERSON/GROUP/UNKNOWN`，状态为 `VERIFIED/UNVERIFIED/CONFLICT`。候选只按唯一的精确稳定 ID 找到；当前选中行 ID 必须与当前详情区域/明确路由 ID 一致。任何可见 ID 或类型冲突都阻止发送。缺少 ID、页面未加载、候选重复、旧临时昵称 Key 均不能被昵称、头像、顺序或包含关系解锁。文字和表情共用这个身份状态门禁，发送前再次核验当前页面。

昵称提取现在读取标题中的最小文本节点，并跳过有 `time/date/weekday/datetime` 语义的节点；不会对昵称字符串全局删除“周日”。身份诊断可报告会话行、其祖先、标题节点、日期节点和详情祖先的标签/类名/身份属性名及证据来源，但不导出节点文本、ID 值、URL、聊天内容、Cookie 或 Token。

## 可复现回归

`tests/browser-v052.py` 使用纯合成页面，不访问抖音。测试先断言旧式 `textContent` 解析会产生“测试对象 周日”，而聊天标题仅为“测试对象”；随后完整执行收集、按稳定 ID 找候选、核验、详情应用、显示名更新和存储恢复。13 项覆盖：

- 星期标签复现及 ID 一致、昵称不同；
- 正常显示名本身含“周日”时保持原样；
- 目标 ID 冲突、缺 ID、同名双联系人和群/个人类型冲突；
- 页面省略 active 标记时只按唯一详情 ID 对应列表行；
- 详情未加载时保持未核验且不能发送；
- 刷新恢复持久化 ID 关系后再次核验；
- 旧临时 Key / 导入联系人不被提升为稳定身份；
- 文字与表情共用发送门禁，`UNKNOWN`/`SUBMITTED` 不重试；
- 已存在完全相同的己方文本时，在写入编辑器或触发发送前阻止重复；
- Build ID 与脱敏 DOM 结构诊断不含名字、ID 值或消息。

## 最终问题逐项回答

1. **为什么之前两轮修复仍失败？** 发布包曾取自旧暂存脚本；昵称前置筛选会先清空候选；旧 ID 读取范围与回归夹具不完整，未复现复合标题和完整匹配链。
2. **真实页面是否存在可用稳定会话 ID？** 目前没有可用的列表—详情交叉 ID 证据：详情与路由未暴露身份 ID；后来观察到的选中行类名只是活动状态标记。未检查到的行祖先 ID 属性仍属未知，不能宣称整个页面绝对没有 ID。
3. **昵称混入“周日”的根因？** 旧代码读取整个标题包装容器的 `textContent`，把昵称和兄弟时间标签拼接。真实 DOM 已确认姓名节点和时间节点分离，修复版读取姓名叶节点；旧配置中的过期显示名仍以未核验状态保留。
4. **新版是否真正消除了这个问题？** 修复选择器与真实 DOM 的姓名/时间节点结构相符，合成回归也通过；但当前列表仍有带星期后缀的未核验变体，来源无法仅凭显示文本判定，因此界面显示层尚不能宣称所有旧记录都已清理。
5. **当前身份是否 VERIFIED？** 插件系统状态仍是 `UNVERIFIED`。本次只基于用户指定目标、唯一可见选中行与同名聊天标题完成一次性人工确认，不持久化为自动发送凭证。
6. **是否执行真实测试消息发送？** 是，向当前可见的指定聊天发送 1 条。
7. **消息是否得到确认？** 是；己方气泡出现在该聊天并显示“已读”。
8. **有没有误发或重复发送？** 未观察到误发；只发送一次，未向其他联系人/群聊发送，也未发送表情。刚创建的测试素材已删除，并在页面复核为 `0/150`。
9. **是否仍有 P0/P1？** 未观察到 P0。P1“自动化身份门禁缺少真实页面稳定 ID 交叉证据”仍开放；因此只能完成本次一次性人工确认测试，不能使用脚本自动发送。
10. **是否可以安全开启自动发送？** 不可以。保持 `scheduled=false`，当前身份系统状态未核实，且火花/重燃状态也不可确认。
