# 抖音火花助手 Full · V0.5.3

非官方 ScriptCat / Tampermonkey 用户脚本及可选本地调度套件。Build ID：`v053-dom-adapter-20261009-r1`。

## V0.5.3 真实 DOM 适配

- 聊天行用真实页面结构识别类型：`commonConversationIconnoDrag` 群聊图标识别为群聊，`commonIMAvataravatarContainer` 用户头像识别为个人；无法唯一识别时保留 `UNKNOWN`。
- 昵称从 `.conversationConversationItemtitle` 节点读取。真实 DOM 中星期/时间节点位于标题包装器的兄弟节点，在线提示位于描述区，不会拼入姓名；旧的无 ID 临时缓存不会按行号复用。
- 列表行的 `conversationConversationItemcurConversation` 只用于识别当前选中行，不作为稳定身份。缺少稳定 ID 时，页面火花信息可只读查看，但联系人状态仍为 `UNVERIFIED`，定时发送继续阻止。
- 火花天数、重燃状态和今日任务分别记录。未读到页面证据时显示未知，不再用默认 1 天冒充已读天数。
- 稳定 ID 缺失时，可对唯一选中的会话进行一次单收件人手动操作确认；确认不保存、不解除定时发送门禁。多收件人手动队列与所有自动发送仍需稳定 ID。
- 更新首次启动会关闭自动发送。原生表情入口在当前真实网页仍是无标签 SVG，脚本不会猜测或点击，需用户手动打开官方面板。

## 当前 Chrome 兼容性证据

真实 Chrome 仍运行 V0.5.2；本轮只读观察确认了上面的列表头像/群图标、标题/时间兄弟节点、当前会话选中类名及输入区结构。聊天列表、详情区没有可供本脚本关联的稳定 ID；当前页面也未观察到火花/重燃专用节点或可识别的原生表情选择器入口。V0.5.3 尚未加载到真实 Chrome，因此本地合成测试通过不等于新版实站已验收。

# 抖音火花助手 Full · V0.4.0

这是在 V0.3.0 源码基础上迭代的**可安装 ScriptCat/Tampermonkey 用户脚本**与可选本地调度套件。V0.4 增加**本地消息素材库、逐好友发送策略、文案轮换和逐好友每日时间计划**。原有好友/群聊核对、火花与重燃读取、发送确认、日志、一言/TXTAPI、周一至周日文案、Windows/Linux/macOS 多账号本地调度仍保留。

> **非官方工具，尚未经过真实抖音账号端到端实测。** 自动发送默认关闭，不能保证消息会被抖音接受或计入火花。对方需知情同意；请勿用于大量陌生用户私信或绕过账号验证。

## V0.4 更新摘要（2026-10-09）

- **素材库**：新增、编辑、删除最多 150 条文字 / Unicode Emoji / 抖音原生表情名称；本地持久化、中文 UI、标签备注；通过「素材」菜单进入。原生表情素材仅保存**官方面板中的准确名称**，并非图片/表情文件。
- **逐好友规则**：从「会话 → 发送策略」或「计划」进入，可按好友设置启用/暂停、分组备注、沿用全局模板 / 单条固定素材 / 多条按顺序轮换；每人可沿用全局时间或设置独立 `HH:mm` 本地发送时间。
- **轮换与防重复**：预览不会推进轮换，明确从 DOM 观察到新己方消息后才会推进。发送后结果为 `UNKNOWN` 时冻结轮换；人工确认 `CONFIRMED` 后推进。老的 TXTAPI/每周文案轮换也改为**确认后推进**。
- **自动执行严格边界**：原生表情包一律不进入定时任务；素材选择无效时跳过。定时只对个人、稳定会话 ID、当前会话交叉验证等条件满足的会话运行，且依赖聊天页面保持打开、可见、登录有效。
- **安全升级与备份**：维持 `spark-full:v2:` 存储命名空间。升级保留 V0.3 保存的好友、设置与任务，但强制关闭自动发送一次。高级页导入/导出会保留素材和好友规则；历史 V0.3 备份仍可导入，导入后始终关闭自动发送。不会导出回调 token、Cookie 和浏览器 Profile。
- **健康诊断**：增加素材数量、专属时间规则数、素材不可执行规则数量的统计，导出诊断仅包含匿名汇总。

### 从 V0.3 安装/更新（Windows Chrome/Edge）

1. **先在旧版高级页导出备份**，停用旧脚本和其他同类自动发消息脚本。一个账号同一时刻只运行一个脚本。
2. 在 ScriptCat / Tampermonkey **编辑原脚本**，将 `douyin-spark-full.user.js` 完整替换保存（推荐原条目升级，存储更容易延续）；或新建用户脚本。
3. 打开 `https://www.douyin.com/chat` 手动登录，右下角点击 `🔥 续火` 展开。默认只显示小悬浮入口。
4. 到「素材」添加几条文案。例如名称 `早安`、类型 `文字`、内容 `早上好，[昵称] 🔥`；可再添加 `晚安 🫶` Emoji。
5. 在「会话」勾选**一位同意接收消息的好友**，点击对应「发送策略」，选择「从多条收藏素材中轮换」并勾选两条。可设置单独发送时间。

### 本版本的已知限制

- **尚未验证真实抖音 DOM、火花重燃检测、私信成功率。** 通过的是本地夹具自动化与模拟浏览器测试。
- 抖音**原生表情包自动发送仍未实测**。素材库仅保存其“准确名称”，通过「发送 → 实验：官方表情包准确名称」执行人工确认的单次试发；定时不触发原生表情包。
- 个人独立时间依赖聊天页面**持续保持打开且前台可见**。随包附带的本地 Python 多账号调度器仍按账号的**全局启动时间**启动浏览器，不会为每位好友单独唤醒浏览器。
- 独立时间同一天内按发送时间加宽限窗口执行，不自动延续到次日凌晨；关闭浏览器、断网、验证码、抖音页面改版均可能造成跳过。
- 素材只会进入发送文字编辑器或官方人工表情面板，不会调用或绕过抖音私有接口。
- 功能上保留一言、TXTAPI、每周专属文案、重试及多账号工具；实际消息行为依然以真实抖音验证为准。

## A. 最简使用：只装油猴脚本

1. 在 Chrome 或 Edge 安装 [ScriptCat](https://docs.scriptcat.org/) 或 Tampermonkey。
2. 在脚本管理器中创建新脚本，把 `douyin-spark-full.user.js` 的完整内容粘贴进去并保存启用；有些脚本管理器支持直接导入 `.user.js` 文件。
3. **停用旧版 ScriptCat-Douyin-Fire-Helper / Spark Lite 及其他同类自动发送脚本**，否则可能重复发送。
4. 打开 `https://www.douyin.com/chat`，手动登录，等待聊天列表出现。
5. 页面右下角默认只显示 `🔥 续火` 小按钮；点击展开，按住拖动可以调整位置。
6. 在「会话」中点 **扫描更多**，逐个核对个人/群聊、昵称、头像、火花天数；点「详情」进入真实会话读取「重燃」。没有可靠证据时显示未识别，不能仅凭天数推断。
7. 选择一位**同意接受消息的测试好友**，进入「发送」编辑文案，点击「预览最终文案」，然后点击「立即批量发送」。确认实际聊天记录。若提示 `UNKNOWN`，先人工核对，不要连续重试。
8. 稳定后才可进入「定时」显式开启每日自动发送。浏览器必须持续运行，网页需可见、已登录，且不能绕过安全验证。

**原生表情包：**「打开原生表情」可尝试点击抖音官方表情面板。下方「试发指定原生表情」是实验功能，仅手动执行、一次一个对象、按你输入的**准确素材名称**尝试在官方弹层中唯一匹配并点击。找不到唯一匹配就停止。**尚未在抖音真实网页验证，不能保证实际发送成功，更不支持定时发送原生表情包。** Unicode Emoji 可以作为文字使用。

## C. Windows 使用本地多账号调度

需要 Python 3.10+，推荐 Chrome 或 Edge。

1. 解压完整 ZIP，在资源管理器打开 `tools` 文件夹。
2. 双击运行 `start-manager.ps1`（或在 PowerShell 中执行 `python manager.py`）。第一次运行会自动从示例生成不含账号的 `config.json`。
3. 点击「添加账号」，填写唯一的账号备注、浏览器、独立 Profile 文件夹路径、发送时间（例如 `20:30`），为每个账号生成一串随机回调令牌。
4. 点击「打开账号」。独立浏览器窗口第一次可能未安装 ScriptCat：**需要在该 Profile 单独安装脚本并手动扫码登录。**
5. 在这个 Profile 的火花助手 →「高级」中启用「允许本地调度器接收完成通知」，填入和管理器一致的回调端口（默认 `7788`）和令牌；在「定时」中将发送时间设置成与该账号配置相同，并在首次手动确认发送行为后再开启自动发送。
6. 在管理器点击「检查配置」，确认能找到浏览器；点击「启动每日调度」才进入真正的本地守护进程。或者在 PowerShell 执行：

```powershell
cd tools
python scheduler.py check
python scheduler.py daemon
```

`python scheduler.py once` 会立即打开各个 Profile，但**不会强制越过脚本自身的自动发送时间或开关**。如果没有到时或未选好友，等待回调后会超时。这是预期的保护措施。

**多账号注意：** 每个浏览器 Profile 必须独立安装并配置用户脚本；用户脚本数据属于各 Profile 的私有存储，不能通过简单复制 `config.json` 共享登录。回调监听只允许当前一个账号发送，因此按账号顺序处理。管理器复制 Profile 会复制本地敏感数据，操作前请确保来源浏览器已退出，不要分享 Profile 文件夹。调度器需保持电脑开机，不能代替 GitHub Actions。
