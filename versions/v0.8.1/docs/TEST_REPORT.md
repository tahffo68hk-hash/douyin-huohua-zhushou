# V0.8.1 发送链路报告

## 对照结论

参考脚本通过输入框的原生 `value` setter 与输入事件搜索联系人；发送时聚焦 Slate 编辑器，使用 `execCommand('insertText')` 输入，再派发 Enter 键事件。它等待约 1.2 秒便记录“发送成功”，没有检查新增己方消息，因此这条日志不能单独证明消息已发出。

V0.8.0 的真实问题更具体：V0.7.1 单会话真实 Chrome 记录已证明会话定位、切换、U+200B 编辑器识别和 `execCommand('insertText')` 写入成功。真实页面的发送控件是 `svg.e2e-send-msg-btn`，无按钮祖先；V0.8.0 源码仍将它映射到父级 DIV 并对 DIV 调用 `.click()`。这一动作没有让脚本观察到新增己方消息，编辑器保留正文。

新粘贴的分析提出搜索定位、四层搜索范围和消息节点计数可能导致失败。这些是值得后续验证的风险，但那次真实单会话的第一处已证实失败阶段在发送动作：目标标题与输入均已通过，SVG 也确实在搜索范围内。本次不扩大改动。

## 修复

V0.8.1 在写入正文并核对标题后，只使用参考脚本的编辑器 Enter 路径。提交前仍写入当日发送意图。提交后只在出现新的精确匹配己方消息且编辑器清空时标记“网页已确认发出”。如果页面忽略合成 Enter 或证据不足，保留 UNKNOWN 并停止，不尝试第二次提交。

没有复制参考脚本的清空用户草稿、模糊昵称点击、1.2 秒后直接记成功或自动重试。

## 失败优先回归

同一隔离 Chromium 夹具使用抖音编辑器、消息及 SVG 的实际 DOM 形态，发送处理器只监听编辑器 Enter，不监听父级 DIV。

| 阶段 | 观察结果 |
|---|---|
| V0.8.0 红灯 | `sent=[]`，编辑器保留正文，父级点击 1 次，Enter 事件 0 次，新增己方消息 0 条，状态“消息待核对”。 |
| V0.8.1 绿灯 | Enter 事件 1 次，新增己方消息 1 条，正文一致，编辑器清空，脚本报告已确认 1 条。 |
| 忽略合成 Enter | 没有新增消息，发送意图保留，状态“消息待核对”；没有点击 SVG 或父级，没有第二次提交。 |
| JavaScript 语法 | `node --check` 通过。 |

测试只证明这一路径在接受合成 Enter 的编辑器实现中可行。按 [MDN 对 `Event.isTrusted` 的说明](https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted)，脚本派发的键盘事件 `isTrusted` 为 `false`；真实抖音是否接受，需要另一次明确授权的单会话真实验收。不能把本地绿灯称作真实发送 PASS。
