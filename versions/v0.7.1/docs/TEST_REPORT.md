# 抖音火花助手 V0.7.1 自动发送失败排查报告

**版本**：V0.7.1  
**Build ID**：`v071-real-editor-send-fix-20261009-r1`  
**结论类别**：源码与隔离 Chromium 回归已修复；真实 Chrome 只完成只读检查和不提交的编辑器干跑，未执行真实发送。

## 自动发送失败的真正原因

V0.7.0 的第一处真实阻塞发生在编辑器输入前：抖音当前编辑器空白时仍有一个 U+200B 零宽占位符。旧版 `plain()` 只折叠普通空白，因此 `runOne()` 第 657 行把空输入框当成已有草稿并返回 `FAIL`，从未执行输入或发送。真实 Chrome 的空白编辑器 `textContent` 只含 U+200B；用不提交的测试文本键入后，正文后仍保留 U+200B，旧版第 667 行的逐字核验也会失败。

即使绕过这两处，旧版第 674–677 行只搜索有文字的 `button` / `[role=button]`。本轮真实 DOM 中的发送图标是 `svg.e2e-send-msg-btn`，位于 `div.messageMsgInputinputAction` 下，不符合旧选择器；旧代码随后派发合成 Enter `KeyboardEvent`。该事件不是可信键盘输入，不能作为抖音接受发送的证据。

因此，**本轮确认的第一处失败是第 11 步“编辑器草稿检查/输入”**；发送控件选择器是后续独立阻塞。不是会话标题误配，也不是测试里成功造出的气泡。

## 根因代码与修复

- V0.7.0 `runOne()` 第 657 行：`plain(editor.textContent)` 将 U+200B 当作真实草稿，直接 `FAIL`。V0.7.1 在 [douyin-spark.user.js](../douyin-spark.user.js#L31) 增加仅去除编辑器首尾 U+200B 的读取函数；草稿保护、第 660 行输入前判断、第 670 行正文核验和第 695 行发送后空框判断统一使用该函数。正文内部字符不变。
- V0.7.0 第 674–677 行：发送控件选择漏掉真实 SVG，合成 Enter 不是可信输入。V0.7.1 第 674–688 行识别唯一可见的 `e2e-send-msg-btn`，点击它的 HTML 父节点；没有唯一、可用控件时，在写入提交意图前停止，并保留编辑器内容。删除合成 Enter 兜底。
- V0.7.1 第 713 行：任何目标缺少稳定 ID 时，多联系人队列会被拒绝；单联系人仍需本轮前台确认，确认框会说明仅按精确名称和类型临时核对，不会保存长期授权。
- 测试读取 UTF-8 文件时显式指定编码；浏览器测试会自动发现 Windows Chrome、PATH 中的 Chromium 或接受 `CHROMIUM` 覆盖值。

## 之前的测试为什么没有发现

原 `browser-smoke.py` 把编辑器设为空字符串，发送入口是普通 `<button id="official-send">`，并由夹具的点击监听器直接添加成功气泡、清空编辑器。它没有抖音的 U+200B 占位符，也没有 `e2e-send-msg-btn` SVG、Slate/editor-kit 内容结构或真实 DOM 事件边界。`browser-safety.py` 复用了同一夹具。16 项 Node 单元测试主要验证迁移、数据保存和静态状态，没有执行 `runOne()` 的真实 DOM 路径。此外，Windows 默认 GBK 还曾使 `browser-safety.py` 在读源码时提前崩溃；V0.7.1 已修复。

## 真实 Chrome 验证边界

- **已做**：只读检查真实页面行数、类型、稳定 ID 属性、当前标题与编辑器结构；在当时空白编辑器中键入唯一的“不发送”标记，确认正文显示并观察到尾随 U+200B，再用编辑区选区删除；最终确认编辑器恢复为仅含 U+200B 的空白状态，当前会话未改变。
- **未做**：没有点击联系人行、自动切换会话、安装/替换 Tampermonkey 脚本、运行 V0.7.1 `execCommand`、点击发送图标、提交私信或等待真实己方气泡。没有改变 Chrome 登录信息或 Profile。
- 所以 V0.7.1 在当前真实抖音页面是否能够通过脚本输入、点击 SVG 发送并确认新气泡，**尚未证明**。本地模拟通过不能替代该证据。

## 最终问题的直接回答

- **真正原因**：先是 U+200B 被误认成已有草稿；接着精确输入比较也被 U+200B 影响；最后旧发送控件选择器漏掉真实 SVG 并退到合成 Enter。
- **第一处失败**：V0.7.0 `runOne()` 第 657 行（本修复版对应第 660 行草稿判断）。
- **为什么旧测试漏检**：模拟编辑器没有 U+200B，发送按钮是普通带文字的 `<button>`，点击事件直接假造了成功气泡。
- **改了什么**：编辑器边界占位符判断、真实 SVG 发送图标父节点点击、无可用控件时提前安全停止、无稳定 ID 多人队列拦截；补充真实形态回归并修复 Windows 测试编码/Chrome发现。
- **当前能否自动切换、输入、触发发送、确认新增己方消息**：隔离模拟均通过；当前真实页面上自动切换、脚本输入、发送和新增己方消息检测均未实测。真实 Chrome 的人工干跑只证明可见编辑器接受键入，不证明脚本路径。
- **误发/重复发送风险**：本轮模拟中，缺少唯一控件时不会创建提交意图；提交后无确认或页面切换则标记 UNKNOWN 并停队列；同日重复被阻止。真实端到端误发风险仍未通过实测排除。
- **真实 Chrome 是否验证**：做了只读 DOM 和不提交输入干跑；没有真实发送。
- **是否可启用一键多好友发送**：当前真实页面没有稳定会话 ID，因此 V0.7.1 会拦截多联系人队列；可以逐位单独选择并每次确认。稳定 ID 的隔离模拟可多联系人运行，但真实页面上的该能力尚未验收。
- **尚未解决**：抖音是否接受脚本对 SVG 父节点的点击、`execCommand` 是否同步 editor-kit 内部状态，以及真实发送后的气泡结构/更新时间表现。它们需要一条用户明确授权的真实单会话消息来确认；本报告没有发送该消息。
